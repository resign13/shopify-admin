# 再来一单与账号独立订单草稿

## 入口及使用

- 订单列表和订单详情的“再来一单”打开新订单表单；原订单不变。复制客户、收货资料、数量、备注和辅料附件，采用当前真实尺码价格，沿用可修改的运费。
- 新增订单、再来一单均可“保存草稿”。客户、地址、商品还未填完也可保存。编辑已有正式订单仍直接保存修改。
- “我的草稿”默认按最后保存时间倒序，每页 10 条，可按联系人、客户、公司和来源订单号搜索，支持继续编辑和删除。
- 草稿保存在 PostgreSQL `admin_order_drafts`，按后台账号创建人隔离；业务员只读写自己的。管理员可切换“全部草稿”，其他创建人的草稿只读，不能代改、删除或提交。
- 保存成功后提示服务器保存时间；未保存的继续编辑内容在关闭时确认放弃。不做后台自动保存，不把浏览器缓存作为正式草稿存储。
- 恢复草稿按当前商品资料重新检查价格、尺码和库存。失效商品保留为待处理项，不默默丢弃。重量只按当前数据计算，不存快照。

## 事务与接口

- `GET /api/admin/orders/{id}/reorder-draft`：只读来源订单及批量商品快照，管理员/外贸且具有 orders 权限，外贸还校验来源归属。
- `GET/POST /api/admin/orders/drafts`：列表或首次保存；首次保存带随机 `draftKey` 和 `draft` 白名单文档，网络重试不重复新增。
- `GET/PUT/DELETE /api/admin/orders/drafts/{id}`：查看、保存和删除；修改/删除带 `version`。并发冲突 409，当前页面输入不被覆盖。
- `POST /api/admin/orders` 复用正式建单事务，返单带 `sourceOrderId`，已保存草稿另带 `draftId`、`draftVersion` 及服务器提供的 `submitRequestId`（作为 requestId）。
- 提交时重新检查权限、有效客户/商品、尺码、当前价格。返单和保存过的草稿如价格变化，返回 409 `reorder_price_changed`，带逐项新价格；更新页面金额，用户再次确认才提交。
- 草稿提交、库存扣减、订单事件和幂等回执同一事务。成功后草稿状态变为 converted，并清空草稿正文；保留最小关联信息防止重复转单。删除同样保留最小 deleted 回执，不删除附件文件。
- 普通保存草稿不生成订单、不扣库存、不产生新订单事件或订单修改日志。后台审计只记草稿操作及版本，不复制客户/备注全文。
- 继承附件按来源订单白名单校验，历史附件不截断；移除引用不删除原文件。新增图片与保留图片合计最多 9 张，历史超限可原样保留；替换 PDF 前先移除保留的 PDF。

## 存储与兼容

- 新增表为后台专用，不修改 orders 的状态枚举或商城下单接口。后台初始化/迁移幂等创建，不清空已有草稿；商城不依赖该表。
- 不把草稿加入正式订单列表、经营统计、库存、导出和语音提醒。草稿不设自动过期；用户主动删除，正式提交后从草稿列表移除。
- 当前版本仅新增和返单草稿。仓库、客户无草稿接口权限；跨账号登录不会从浏览器恢复前一个人的草稿。
- 本地手动服务仍使用 `127.0.0.1:55439/lumiere_admin`；测试和浏览器夹具必须使用独立 `*_test` 库。固定数据库同步脚本与自动化位置不变。
