# 独立临时入库

## 使用与核算

- 登记库存抽屉在原有表格最后追加「临时待入库」列，按颜色 SKU 的真实尺码填写非负整数；不另设登记区块。
- 保存只登记数量，可修改、减少、清零。它不占用合同未送、待验货、采购待入库，也不提前增加现货或商城可买数量。
- 「临时入库」展示该 SKU 所有已登记尺码的数量和前后现货余额，确认后整笔增加现货并清零临时数量。例如现货 -5、临时 8，处理后现货 3、临时 0。
- 原「一键入库」仍只处理采购待入库。两个入口互不清零对方来源，合同未送及待验货均保持原值。
- 管理员、外贸和仓库沿用库存模块编辑权限；客户接口不显示临时数量。
- 库存列表、尺码展开、经营库存汇总包含临时数量，但可用现货、周转天数不计入它。下架且仍有临时数量的商品仍可在库存管理处理。

## 数据与接口

- `product_size_prices.temporary_inbound`：INTEGER、NOT NULL、DEFAULT 0、CHECK >= 0；最大 2147483647。
- 内部尺码对象：`temporaryInbound`。
- `PUT /api/admin/inventory/{id}`：原请求额外支持 `temporaryInboundBySize`，例如：

```json
{"version":"最新商品版本","sizeStocks":{},"temporaryInboundBySize":{"M":8,"L":2}}
```

- `POST /api/admin/inventory/{id}/temporary/receive`：仅传 `version` 和 UUID `requestId`。实际数量以数据库已保存值为准，不接受客户端指定入库数量或切换来源。
- 普通入库仍为 `POST /api/admin/inventory/{id}/receive`，旧回执指纹保持兼容。
- 入库事务锁定商品与尺码，检查版本及尺码/父商品整数范围，更新父商品合计，写入回执和审计。重复请求只入库一次；不同来源、操作者复用请求号不被视为同一操作。
- 版本过期返回 409；页面支持重新读取数量、确认新预览。临时数量全零、输入非法或越界均不写库存。
- 商品资料保存保留现有临时数量，禁止删除或改名仍有临时数量的尺码；删除关联商品仅下架而非清除数量。

## Excel

- 新模板 `inventory-v4` 保留既有列，追加 Q「临时待入库」及隐藏 R「原始临时待入库」。
- 预览、原值比较、字段冲突、全文件事务、审计和重复文件回执延续原机制。导入只保存，不触发入库。
- `inventory-v1/v2/v3` 仍支持，缺少临时列时保留数据库原临时数量。公式、负数、小数和越界拒绝写入。

## 登记操作记录

- 登记抽屉下方按当前颜色 SKU 展示记录，默认每页 10 条，按操作时间及 ID 倒序翻页。
- 每次成功的库存登记保存仅记录一次操作，即使同一次保存修改多个尺码、多个阶段；无效输入、版本冲突和事务失败均不新增记录。
- 保存真实操作人的 ID、姓名和角色快照、时间、SKU，以及每个变化尺码的现货/合同未送/待验货/待入库/临时待入库原值、保存值和差额。包括采购阶段自动联动产生的变化。
- 记录与库存、审计同事务提交，写入失败整体回滚。操作者改名不改写历史记录。
- `GET /api/admin/inventory/{id}/operations?page=1&pageSize=10` 返回 `items/total/page/pageSize`，管理员、外贸、仓库沿用库存模块权限；客户及无库存权限账号不开放。
- 专用表 `inventory_registration_logs` 只记录登记保存，一键/临时入库、下单扣库及 Excel 导入继续通过原有审计/回执追踪，不混入登记保存次数。不把旧的逐字段审计推测补写成保存记录。

## 迁移与验证

- 两端共用相同库存策略迁移，重复执行不清零、不重新分摊已存在库存。
- 回滚版本需要保留新增字段、读写和尺码保护兼容，不能删列清零。
- 库存开发使用独立 `feature/inventory-temporary-inbound` 工作目录；账号关联改动留在 `feature/sales-account-ownership`。原每日线上数据库同步脚本及自动化位置不变。
- 自动化回归及自动化浏览器验证使用独立 `*_test` 数据库，禁止对线上或本地同步镜像执行测试模块。本地手动验证统一使用线上同步库 `127.0.0.1:55439/lumiere_admin`，保留真实账号和密码。
- `scripts/start-local.ps1` 固定连接同步镜像并注册当前配对工作目录，现有同步脚本在替换镜像前同时执行这些目录的迁移，避免每日同步后运行中的功能分支缺少新增列。同步脚本位置、每日计划与远程只读方式保持不变。
- 管理端回归模块：`test_temporary_inbound`，覆盖独立登记、来源隔离、负库存、并发/幂等、版本冲突、商品编辑保护、Excel 兼容、权限、汇总、整数溢出及迁移。配对商城仓库时额外执行跨服务迁移及实际购买校验；单仓库 CI 仍执行后台迁移与库存回归。
- 商城模块：`storefront-backend/test_temporary_inbound.py` 验证递归隐藏字段和临时数量不计入可买库存。
- 将来与账号关联分支合并时，个人经营视图的库存字段屏蔽清单也应包含 `temporaryInbound`，本分支不引入账号关联功能。
- 发布顺序：先商城库存读取兼容，再后台登记、入库与操作记录。既有发布流程继续备份代码和数据库，新增采购/临时数量指纹及只读验证；已有临时字段后，禁止自动恢复不保留它的旧代码。
