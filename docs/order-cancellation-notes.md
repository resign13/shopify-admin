# 订单取消备注

- 后台取消订单可选填 500 字取消备注，与普通备注分开。
- 列表状态菜单、详情快捷状态和完整订单编辑共用同一服务端规则。
- 已取消订单详情可补填、修改、清空；仅提交 `cancelNote` 和 `version` 时只修改备注。
- 列表有备注时显示可悬停、聚焦或点击的图标。详情及订单操作记录保留完整文字。
- 后台继续执行订单模块授权与业务员归属隔离；商城和客户导出不返回内部备注。
- 恢复订单清空当前备注，原内容留在审计中。再次取消默认空白。返单和草稿不继承。
- 状态、备注、库存和审计在原有同一事务内提交；陈旧版本返回 409。
- 取消弹窗在冲突后保留输入，读取最新版本后须再次明确确认，不自动重放。

## 数据兼容

两端 `order_cancellation.migrate` 和初始化 SQL 均幂等添加
`orders.cancellation_note TEXT NOT NULL DEFAULT ''` 以及 500 字长度约束。
不重写原备注、订单号、金额、附件或历史订单状态。
商城取消仍只走原流程，不接受后台取消备注。

## 验收

自动化仅运行在独立本地 `*_test` 库，包含取消、补改清空、恢复、重复/并发、
回滚、权限、全量编辑、返单、导出及两端迁移兼容；浏览器覆盖桌面和窄屏交互。
手动页面使用当前分支以及本机同步库，不创建或重置账号。

本次与详情库存一并本地验收、提交 PR；部署须在双方 CI、备份和数据库预检通过后，按用户确认的维护窗口进行。
