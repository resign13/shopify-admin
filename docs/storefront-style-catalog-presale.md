# 款号目录与预售管理（本地功能分支）

## 业务边界

- 商城 `/shop` 为默认目录；`/presale` 为独立展示专区。整款展示全部已上架颜色，仍按现货下单，不产生新的订单类型。
- 款号身份优先使用显式 `style_code`，其次使用不同于商品编码的 `color_group`，最后使用商品编码去除最后一个颜色后缀。与详情颜色切换一致，不按标题合并。
- 自动排序使用全部颜色（含下架）的最早创建时间、最早商品 ID 倒序。手动预售排序跨分类；新增款号追加末尾。旧活动不会自动迁入预售。
- 后台预售编辑为草稿，保存成功才生效。冲突保留草稿并要求读取最新配置。下架整款保留选择；无法解析的旧款号标记重新选择。

## 接口与权限

- `GET /api/admin/presale`：`config`（`styleCodes`、`sortMode`、`version`）及完整款号选择数据。
- `PUT /api/admin/presale`：提交上述三项，固定顺序加锁并比较版本；冲突 `409`，保存与审计同事务。
- `GET /api/catalog/styles`：登录后按款号筛选及分页；参数 `section=shop|presale`、`keyword`、`category`、`stockOnly=1`、`page`、`pageSize=12|24|36`、`lang`。
- `GET /api/catalog/categories`：替代分类导航对旧首页配置接口的依赖。
- 预售管理仅管理员及被明确授予 `presale` 的外贸；外贸 NULL 默认权限不包含预售。仓库、客户不开放维护。无权的直接接口调用仍被拒绝。
- 目录采用单次只读一致性快照及批量商品资料查询，不逐颜色查询，不返回重量及内部采购字段。旧扁平商品接口继续用于详情、购物车和库存。

## 兼容性

两端重复迁移仅增加 `products.style_code` 及单行 `presale_configs`，不覆盖配置、不删除历史数据。旧推荐标记、图片及首页／活动配置保留；商品保存省略推荐字段时保持原值。后台旧首页和活动写入接口返回 `410`，旧只读接口保留兼容。

发布、回滚均须保留新表和字段；日常只读数据库同步脚本保持固定位置。

## 发布检查

两端通过现有 GitHub Actions 发布，先后台、再商城。现有代码／数据库备份、共享部署锁和健康检查流程保留。新增 `scripts/verify-style-catalog.py` 在 CI 及服务器发布后使用只读一致性事务核对款号结构、预售配置、首次上架顺序、权限与可用库存；不创建登录会话或写入业务数据。

本次商城同时包括英文界面及错误提示、款号和颜色库存（欠货显示为 0）、尺码行重复标题清理。金额、库存扣减、订单归属及商品重量逻辑不调整。
