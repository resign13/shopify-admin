# 财务管理

## 入口与权限

后台 `/finance`，默认“成本统计”，另有“商品成本”。新建后台账号可选择“财务部”，默认仅勾选财务管理。管理员可通过后台账号界面明确授予或撤销该模块。

- 未限制模块的管理员兼容默认权限；已有显式权限列表不自动扩权。
- 仅 `admin` / `finance` 且拥有 `finance` 模块权限可访问所有财务接口。
- 外贸、仓库、客户无入口，直接请求返回 403。财务部不获得订单、商品、库存、账号管理权限。
- 成本及成本变更详情仅在财务接口返回；不混入普通商品、订单、库存和操作日志。

## 操作口径

1. 商品成本按完整款号分页，每页 12 款；只展示款号、颜色 SKU 和真实尺码，不展示商品标题，SKU／颜色筛选不再匹配标题。真实尺码矩阵不新增缺失尺码，下架商品仍可维护。
2. 查询时选择成本生效日期，页面明确显示正在编辑的日期；改变日期后点“查询 / 应用日期”。
3. 勾选颜色 SKU、选择真实尺码或全部尺码、填写人民币单件成本并“批量应用”，只改页面草稿。“清空”使用同一勾选范围与尺码，确认影响数量后将草稿改为未设置，点击“保存成本”才生效；已有零成本也可清空。未选择或没有可清空值时按钮禁用，不新增缺失尺码、不处理其他颜色。选择跨查询、分页不保留。
4. “保存成本”先预览原值、新值、生效区间、受影响有效订单数；确认才提交。未保存离开可取消离开、继续保留草稿。刷新/关闭浏览器不持久保存成本草稿。
5. 空白代表未设置，显式 `0.00` 才是零成本。清空保存为所选日期生效的 `NULL` 成本记录，而非删除记录；不回退使用更早成本，直至下一条成本生效。生效日期以前仍匹配当时成本；同日更正的旧金额保留在审计中。每款仅一个“成本历史”入口，弹窗默认展示整款所有颜色和尺码，清空显示“原金额 → 未设置”，可按颜色和尺码筛选；每页 20 条，按保存顺序倒序。历史查询、筛选和关闭不影响成本草稿。
6. 每个商品 ID + 真实尺码按北京时间订单日期匹配最近且不晚于该日的成本。首次录入不会补覆盖更早订单。补录历史日期会改变重新查询的历史报表。
7. 销售额采用订单商品行保存的成交价×数量，不含运费；手动填写汇率，最多 6 位小数。汇率与导出位于页签行右侧，点击“保存汇率”保存一个全局公共值，管理员及财务账号共用，重新打开页面自动带入；不是按账号或浏览器分别保存。修改后重新查询才更新报表，汇率和已查询结果不一致时暂停导出。每行人民币折算四舍五入到分，再汇总。
8. 默认最近 30 天及五种有效订单状态，排除取消和草稿。客户、业务员、状态为查询时当前信息；款号只筛选命中的商品行。
9. 缺失成本不作零处理。显示已知成本、缺失件数、已设置部分毛利，完整成本和整体毛利待补全。
10. 导出沿用最后一次成功查询的条件，重新读取一个数据库快照，包含全部结果而非当前分页。三个工作表：核算汇总、订单明细、成本缺失；客户输入强制文本，货币列为数值。

## 接口

统一 Bearer 登录认证。路径前缀 `/api/admin/finance`：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/options` | 财务专用客户、业务员、款号、分类选项 |
| GET | `/preferences` | 全局公共汇率及修改版本；未设置为 `null` |
| PUT | `/preferences` | `{exchangeRate,version}` 保存公共汇率，仅财务权限可用；同值重试不重复递增版本，冲突返回 409 |
| GET | `/costs` | 按款分页的成本矩阵，`effectiveDate`、`styleCodes`、`keyword`、`category`、`missingOnly` |
| GET | `/costs/history` | 新模式：`styleCode`、可选 `productId` / `sizeCode` / `page`，每页 20 条整款审计与颜色、尺码选项；原 `productId` + `sizeCode` 模式继续返回时间线与每页 10 条审计 |
| POST | `/costs/preview` | `{effectiveDate, changes:[{productId,sizeCode,costCny,version}]}` |
| POST | `/costs/save` | 预览请求 + `previewHash` + UUID `requestId` |
| POST | `/reports/query` | 日期、客户关键词/账号、业务员数组（含 `unassigned`）、款号数组、状态、汇率、分页 |
| POST | `/reports/export` | 同统计筛选，忽略当前页，下载 XLSX |

金额 API 为精确十进制字符串；成本缺失为 `null`。修改版本或预览影响范围变化返回 409，整批无部分成功。相同请求编号和内容重试返回原回执；换内容或身份复用编号返回 409。

成本批量预览／保存的 `changes[].costCny` 允许显式 `null` 表示清空；字段省略、空字符串、布尔值或无效金额仍拒绝，避免旧客户端意外清空。保存照常进行影响预览、版本校验、事务及幂等回执。清空影响的报表商品行计入缺失成本，而非零成本，完整成本和毛利待补全，Excel 列入“成本缺失”。

整款历史返回 `items`、`total`、`page`、`pageSize` 和 `options.variants` / `options.sizes`。明细包含 `productId`、保存时 `sku`、`sizeCode`、`oldCostCny`、`costCny`、`effectiveDate`、`actor`、`createdAt`。新生效日期记录的原成本取已保存审计中的 `oldCostCny`，不从当前成本反推。现存商品按与矩阵一致的当前款号定位；已删除商品按审计保留款号定位，已移除尺码仍保留在筛选和历史内。不新增表、不改写审计数据。

## 数据与兼容

独立 `finance_cost_history`、`finance_cost_versions`、`finance_cost_audit`、`finance_cost_receipts` 四张成本表；逻辑商品/尺码键，不引用会重建的尺码行 ID，不级联删除历史。另用 `finance_settings` 单行保存公共汇率、版本与最后修改人；数据库锁和版本检查避免多人覆盖，重复启动不覆盖已保存值。初始化 SQL 与后台启动迁移一致，重复运行不重置。

`finance_cost_history.cost_cny` 调整为可空；旧库迁移仅移除该列的非空约束，保留非负检查及原记录，新库和重复初始化兼容。`NULL` 是明确的未设置生效节点，读取最近节点时不能增加 `cost_cny IS NOT NULL` 过滤，否则会错误回退旧成本。

商城无需接入成本，原共用库结构只作增量扩展；不更新订单、库存、采购阶段或通知。成本保存与日志、版本、回执在同一事务。读取/导出使用 repeatable-read 只读快照。未来回滚保留财务结构与公共设置，不删历史数据。
