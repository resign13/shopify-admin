# 财务管理

## 当前口径（2026-10-15）

- **每个款号仅一个人民币单件成本，全部颜色、全部尺码共用。** 沿用目录的明确款号规则，不根据商品标题合并。
- **每款首次成本覆盖此前订单；后续改价按订单下单时间匹配。** 第一次实际填写金额（包括明确的零）会补算该款全部历史订单；之后从服务端本次保存时间起生效，只影响新订单。无需手动填写生效日期，同一天多次保存也按准确时间区分。
- 例：首次填写 12 元，此前订单也按 12 元核算；之后今天 10:00 改为 18 元，10:00 以前的订单保留对应历史成本，10:00 起的新订单按 18 元。清空后的新订单仍为缺失，不按后续恢复的成本补算，也不当作零。
- 已下载的 Excel 不改变；重新查询、导出继续按照各订单下单时间匹配历史，而非读取当前成本覆盖历史。
- 用户确认成本尚未开始录入；本地同步后核对旧成本记录为空。本次不自动合并或猜测旧的变体金额。旧表保留归档，不作为统计金额来源。

## 入口与权限

后台 `/finance`，默认“成本统计”，另有“商品成本”。沿用部门默认与明确模块授权：财务部默认财务管理、合同管理；管理员默认所有模块；已有自定义权限不自动覆盖。拥有财务管理模块权限的内部员工可访问，商城客户不开放。成本及成本变动只在财务专用接口返回，不混入普通商品、订单、库存和通用操作日志。商城运行数据库账号不具有成本表或成本审计表权限。

## 商品成本

1. 每款一行，仅显示勾选框、款号、一个成本输入框与“历史”，不展示商品标题、颜色尺码矩阵或图片。每页 20 款；桌面左右各 10 款，分为两组紧凑录入，平板和手机连续单列，不改变款号顺序及分页。金额带 ¥ 并右对齐，空值和明确零成本保持区分。
2. 保留款号（支持中英文逗号）、SKU／颜色、分类及仅未设置筛选；SKU／颜色命中后维护整款成本。下架商品仍可维护成本。
3. 逐行填写，或勾选款号 → 填写成本 → 批量应用；未勾选时收起批量工具，底部保留保存区与未保存数量提示。按 Enter 进入下一个成本输入，Shift + Enter 返回上一个，不自动保存。覆盖已有不同成本前确认数量。清空对已选款号操作，明确零成本也可清空。查询和分页清空选择，避免隐藏跨页修改。
4. 批量应用、清空仅修改草稿，修改行高亮；点击“保存成本”先预览款号、旧值、新值及生效范围，区分“含历史订单”的首次设置与“保存后的新订单”的后续修改。只有首次设置统计补算的历史有效订单数，后续修改不计历史影响。确认后统一提交，生效时间由服务端数据库生成，整批使用同一时间。离开或重新查询前提示放弃未保存修改，取消可继续编辑。
5. 非负金额最多两位小数；空白表示未设置，明确 `0.00` 才是零成本。清空仅从保存时起变为未设置，之前的订单继续使用原历史成本；清空期间不回退为更早的成本，再次设置也不填补该期间。
6. 每款一个成本历史弹窗：生效时间（北京时间）、原成本、新成本、操作者；首次记录标注“首次设置 · 含历史订单”，倒序每页 20 条。无颜色尺码筛选或手填生效日期。清空记录为“原金额 → 未设置”，保留历史；查看、关闭、重试历史均不影响页面草稿。
7. 新增同款颜色、尺码自动共用该款成本。商品编辑、尺码重建或下架不清空成本，成本与历史不随商品删除而级联删除。款号改变后按新款号匹配，未设置的新款号不猜测旧成本。

## 成本统计与导出

- 保留紧凑筛选、三组金额摘要、展开订单明细及分页。默认最近 30 天及五种有效状态，排除取消和草稿；款号过滤只统计命中的商品行。
- 商品成本为对应历史整款单件成本 × 订单商品行数量。首次实际金额为历史基线（`is_initial=true`），也适用于该保存时间之前的订单；之后匹配 `effective_at <= orders.created_at` 的最近变动，下一条变动之前有效。精确到数据库时间（含时区），不是按付款或查询时间，也不是只按日期。同一统计期间可以出现不同成本，展示成本区间，按行分别核算后汇总。
- 从未填过成本时显示缺失；首次填写后补算。第一次金额前的空白/清空不算首次成本；一旦建立基线，清空后再次填写不会建立第二个基线，也不填补清空期间。
- 销售额仍使用订单保存成交价，不使用当前售价，不计运费。筛选日期采用北京时间；客户、业务员及状态为查询时记录。
- 手动公共汇率最多六位小数，所有财务账号共享。美元销售额按订单商品行折算为人民币，逐行四舍五入到分后汇总，后端精确 Decimal 计算。
- 缺失成本不作为零：完整成本、整体毛利为待补全；分别展示已知成本、缺失件数和已设置部分毛利。不含运费、税费及其他费用，未付款订单不代表实际回款。
- 修改筛选、汇率或在本页保存成本后，旧结果保留并提示重新查询，重新查询前禁用导出。查询失败保留旧结果。
- Excel 仍按最后成功查询条件导出所有匹配行，不限当前分页，整份使用同一只读数据库快照。三个工作表：核算汇总、订单明细、成本缺失。标注历史时间匹配口径和每行匹配的成本生效时间；金额为数值，外部输入强制文本，完整订单号自动换行。

## 接口

使用现有 HttpOnly Cookie 会话，非安全方法验证 CSRF 和 Origin；路径前缀 `/api/admin/finance`。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/options` | 专用客户、业务员、款号、分类选项 |
| GET / PUT | `/preferences` | 公共汇率及版本，写入 `{exchangeRate,version}` |
| GET | `/costs` | 默认每页 20 款（兼容旧 12/24/48 请求）；`styleCodes`、`keyword`、`category`、`missingOnly`、`page`、`pageSize` |
| GET | `/costs/history` | `styleCode`、`page`，每页 20 条整款成本变动；旧 `productId` + `sizeCode` 归档查询仍保留 |
| POST | `/costs/preview` | `{changes:[{styleCode,costCny,version}]}` |
| POST | `/costs/save` | 上述请求 + `previewHash` + UUID `requestId` |
| POST | `/reports/query` | 日期、客户关键词/账号、业务员、款号、状态、汇率、分页 |
| POST | `/reports/export` | 同查询筛选，导出全部行 |

成本金额为十进制字符串，缺失为 `null`；省略成本字段不会被当作清空。旧变体／生效日期写请求明确报错，要求刷新后使用整款表单，不隐式选某个颜色覆盖整款。

`/costs` 每行返回 `styleCode,costCny,version,updatedAt`，用于编辑当前整款成本，无标题与矩阵。预览含原／新成本、每行 `initialCost`、`effectiveMode=initial_then_on_save`，`affectedOrders` 仅计首次设置补算的有效订单并去重；生效时间不参与会变化的预览哈希。保存返回 `effectiveAt`，相同幂等请求重试返回原生效时间。拒绝客户端传入 `effectiveAt`／`effectiveDate`。历史含 `oldCostCny,costCny,actor,createdAt,effectiveAt,initialCost`。统计返回 `costBasis=style_at_order_time`，明细含 `costEffectiveAt` 与 `costMatch`（首次成本补算／下单时生效成本／未设置成本），Excel 一并保留。

## 数据、事务与本地验收

`finance_style_costs` 保留当前成本与乐观版本；`finance_style_cost_audit` 追加式记录原值／新值，并增加不可空 `effective_at TIMESTAMPTZ`、`is_initial`、款号／时间／ID 索引及每款仅一个首次成本的部分唯一索引，直接作为历史核算依据，无需新建每单成本快照。批量 SQL 关联历史事件或首次成本，不逐行往返数据库。独立于商品及尺码行 ID，保留旧变体成本归档、公共汇率表和幂等回执。

初始化 SQL 与显式迁移幂等，已有整款审计的生效时间沿用其原 `created_at`，不改为迁移时间；第一条实际金额标为历史基线，不把最新金额当作首次金额。仅有当前成本无审计的异常旧记录按已知 `updated_at` 建立记录。重复迁移不重置成本、时间、审计或公共汇率。旧按最新整款成本重算的预览哈希不兼容，明确返回 409，要求重新预览，不静默按新口径提交。

保存使用排序后的款号事务锁、乐观版本、预览校验、请求幂等；并发或预览变化整批返回 409。成本、审计及回执同一事务，失败无部分保存；不修改订单、库存、采购阶段、草稿、语音通知或账号密码。后台运行角色按既有最小权限获得新表权限，商城角色继续禁止读取。
