# 业务员归属、关联账号和本地数据库同步

## 管理员操作

1. 在“商城账号 → 编辑 → 关联后台业务员”选择启用的外贸部账号并保存。
2. 该商城账号尚未分配归属的历史商城订单纳入所选业务员；以后商城下单按当前关联自动归属。一个商城账号对应一位业务员，一位业务员可关联多个商城账号。
3. 两端登录账号和密码保持独立，不通过同名、相同邮箱等条件自动关联。
4. “经营工作台”可选择全公司、具体业务员或未分配订单；订单管理提供相同的筛选。筛选后点击“查询”。
5. 管理员代建订单可指定归属业务员，编辑订单也可调整归属；外贸人员建单自动归属本人，且不能修改为他人。

### 历史与权限口径

- `created_by_admin_id` 保留真实建单人员，`owner_admin_id` 独立保存订单业绩归属，`order_source` 区分商城与后台。
- 初始迁移按原建单人员为历史外贸部后台订单补齐归属。管理员代建且没有明确业务员的订单保持未分配。
- 关联时仅填充未归属的商城订单，不改后台订单、其他已分配订单；修改或解除账号关联不自动转移已经归属的历史订单。历史转移由管理员明确编辑订单归属。
- 已取消订单也保留归属，但有效订单销量和商品金额统计排除取消订单，商品金额不含运费。
- 经营趋势、国家分布、状态统计、最近订单、款号/颜色/尺码明细全部使用同一服务端归属过滤。业务员通过参数、详情 ID、幂等重放或导出入口访问他人的订单均被隔离。
- 个人经营视图不展示公司库存快照、库存风险及公司周转；共享库存仍由现有库存模块管理，不按人员复制库存。
- 关联、解除关联、归属修改仅变更元数据，不扣库、不退库，审计随同一事务提交；正常订单数量或状态修改仍按原库存规则执行。
- 有订单归属或商城账号关联的业务员账号保留身份和外贸角色，离职使用停用。商城及兼容接口不公开内部归属字段。
- 迁移标记 `initial-owner-v1` 确保两端重复启动不会重新分配已处理订单。

## 每日生产数据同步

- 每天北京时间 **04:00** 的 Codex 本地自动化已创建，名称“商城后台数据库每日同步到本地”。电脑开机且 Codex 应用运行时执行；正常成功保持安静，失败或需要处理时通知。
- 本地脚本：`D:\dulizhan\shopify-admin\scripts\sync-production-db.py`。
- 单向同步到 `127.0.0.1:55439/lumiere_admin`，两端本地 `.env` 指向同一个镜像库。不会修改本地业务代码、提交主分支或部署。
- 电脑重启后，脚本会按需启动 `D:\dulizhan\output\qa-runtime\pgdata` 的现有专用 PostgreSQL 集群，不重新初始化数据，不操作其他项目的 5432 端口。
- 通过专用 `ops/database-sync` 分支的只读导出工作流申请一致性快照，**不是 main 的部署工作流**；导出不会写生产数据库、重启服务或迁移线上。
- 生产快照用 AES-GCM 加密，密钥用本机 RSA 公钥封装。GitHub 仅保存密文，自动过期时间为一天。私钥位于当前 Windows 用户专用目录，并由 DPAPI 保护。
- 本地先恢复到临时数据库，核对全部表的行数和内容摘要，清除克隆的登录会话，在临时库完成当前代码迁移，再用数据库重命名事务切换。
- 原本地库保留为 `lumiere_admin_backup_日期时间`。临时恢复、核对或迁移失败时保留原有效镜像，不切换。
- 同步是覆盖式更新，本地测试修改不会回传线上；需要保留的本地试验使用独立 `*_test` 数据库。本地备份不会随此次同步删除。
- 私钥、加密快照、同步结果都在 `C:\Users\Administrator\.codex\private\gingtto-db-sync`，不进入业务仓库。结果文件为 `last-sync.json`。
- 同步数据库不复制上传文件实体；订单附件、图片 URL 随数据库保留。本地登录会话在每次同步后需重新登录。
