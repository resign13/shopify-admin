# 部门默认权限与后台图形验证码

## 账号权限

- 管理员、外贸、仓库、财务的部门决定新账号默认勾选，不再限制可选模块。
- 财务默认勾选财务管理、合同管理；其他模块由具有后台账号管理权限的人明确授权。
- 编辑账号保留原明确授权；空权限仍表示全部撤销，不自动恢复默认。
- 既有账号不会因页面升级而覆盖已保存的权限。本次发布按用户已确认的要求，单独补齐旧财务默认账号的合同权限，并记录审计；空权限及自定义授权保留。后续仍按账号勾选和保存。
- 业务员订单归属、草稿所有权及仓库订单操作／金额限制保持不变。
- 权限变更撤销旧会话；重新登录后读取新的权限。

## 图形验证码

- 仅后台登录使用，5 位字母／数字，不区分大小写，点击图片刷新。
- 有效期 5 分钟。每张图只可提交一次，密码错误或验证码错误后均换图。
- 服务端签名挑战，答案不以文本字段返回，不写入日志或明文数据库。共享 PostgreSQL 原子消费防止跨进程重放。
- 保留 Cookie、CSRF、Origin、会话到期等现有边界；验证码不代替账号密码，也不要求手机绑定。
- 验证码接口独立限频，默认每 IP 每分钟 20 次，返回 429 和 Retry-After。
- 加载失败时禁用登录并提供重试，不跳过验证；保留用户已填写的账号和密码。

## 配置及发布

`SECURITY_ADMIN_CAPTCHA_ENABLED=1` 开启；默认 `0` 用于兼容分阶段发布。
`SECURITY_LIMIT_CAPTCHA=20` 设置图片刷新额度。

先发布匹配的后台代码和登录页面，再在后台运行环境明确开启验证码。商城无需开启，现有 6.4 节登录保护开关不随本功能改变。没有新增表或迁移；复用既有安全计数表。

先完成本地和 PR 验收，再按用户授权发布。2026-10-14 用户已明确授权验收通过后执行本次后台短时维护；商城保持运行，不启用附件私有化或 6.4 节登录保护。后续维护仍须重新确认。

## 验证入口

- `admin-backend/test_login_captcha.py`：签名、缺失／错误／过期、一次性、并发、CSRF、限频、兼容开关。
- `admin-backend/test_permissions.py`：默认与明确授权、撤销、财务合同流程、库存及操作审计。
- `scripts/department-permissions-browser-fixture.py`：仅允许本机独立 `*_test` 库，测试图片固定答案只存在于夹具，发布包排除夹具。
- `scripts/verify-login-captcha-browser.js`、`scripts/verify-department-permissions-browser.js`：登录及权限页面验收。
- GitHub CI 包含专用隔离浏览器步骤；真实账号手动页面继续使用本机同步库。
