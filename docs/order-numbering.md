# 新订单编号与展示

## 规则

正式创建的新订单编号为 `PO{北京时间月日}-{订单联系人完整名称}-{全局订单 ID，至少六位}`。
后台建单（包括返单、草稿转单）、兼容建单和商城建单均调用两端一致的 `order_numbering.make_order_number`。
日期取数据库实际保存的 `created_at`，明确转为 UTC+8；不使用浏览器时间。
临时编号为随机值，仅在建单事务中存在。提交后返回最终编号；原订单编号不回填，不重置序列。
客户名字中的内部空格、大小写、重音字符、中文和连字符原样保留。保存草稿不写入订单表或消耗订单流水。

## 迁移与兼容

两端初始化为 `orders.order_no VARCHAR(255)`；启动迁移只扩容旧短列，保持唯一约束及历史编号。
修改客户、状态、归属等操作不重新编号。通知只读取已提交的最终编号。
发布前两端都必须带上同名 `order_numbering.py`，现有数据库备份和迁移步骤不变。

## 页面与导出

订单列表编号列固定 260px，按 28 字符预算只省略客户名称，窄列进一步仅裁切名称。
日期前缀和完整流水始终保留；悬浮和复制使用完整编号。旧 LM 编号保持原显示。
详情及返单标题允许换行，详情抽屉宽度限制为视口宽度；草稿来源使用同一紧凑展示。
商城订单的长编号允许换行。
三种 Excel 表内使用完整编号并自动换行/增加行高；分订单工作表使用 `PO1013-000188` 短名称。
下载文件名仍走现有安全处理，与数据库编号无关。
